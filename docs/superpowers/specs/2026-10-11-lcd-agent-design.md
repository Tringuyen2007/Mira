# LCD agent: Mira's live trainer voice and mascot animation

Branch `LCD-agent` (from `main` at 986bf24). Hackathon scope: make the LCD kiosk feel like a live trainer —
Mira speaks every screen in one ElevenLabs voice, counts correct reps aloud, animates while she talks, and
narrates the emergency-call flow. Screens keep their current layout (Figma "LCD Hi-Fi").

## What exists already (reused, not rebuilt)

- `device/kiosk/`: pure reducer (`state.js`) + view, 10 screens, moods via still PNGs + CSS keyframes, audio
  player that only plays same-origin `/audio/*.mp3`, captions from `live.caption`.
- Server voice: `server/ai/eleven.py` (TTS, disk cache, voice id/model from `.env`), `server/ai/cue_library.py`
  (cue id → 3 text variants + MP3 under `data/cues/mp3`, served at `/audio/`), `SessionVoice` (AI greeting /
  per-set summary), Coach cues, Guardian `cue check_in` + `alert {step, message, show_call_911}` steps
  (`detected → checked_in → resolved | escalated → call_registered → call_ongoing → call_update → call_ended
  → acknowledged → closed`), Retell caller behind `CALLS_DISABLED` (log-only simulator when 1).
- Rep counting: engine (mock today, Eric's vision later) emits `rep {index, set, quality, flags}`; the LCD
  shows `live.rep`. `server/agents/rep_pipeline.py` is the correctness gate Eric will call. **Placeholder:**
  nothing in this branch changes how reps are judged; the LCD counts whatever the engine emits as `rep`.
- Mock session (`MIRA_SOURCE=mock`): `arrived → greeting → awaiting_gesture → gesture → countdown 3-2-1 →
  10 reps (rep 5 has knee cave) → set_done → … 3 sets → session_summary`, auto-restarts every 60 s.

## Constraints discovered

- ElevenLabs key is **free tier: 10,000 chars/month, ~8,000 left**. Every line must be pre-generated once,
  cached and committed; the running server must never synthesize per session. Runtime AI lines (greeting,
  set summary) keep their text/caption but get no fresh audio unless `ELEVEN_RUNTIME_TTS=1`.
- The LCD never shows `innerHTML`; CSP has no inline script/style. Keep that.
- Vultr box `.env` cannot be read from this session (policy); the deploy ships only tracked files. So the
  MP3s are committed (`data/cues/mp3`, ~70 files, ≈1.5 MB) and the box needs **no ElevenLabs key**.

## Design

### 1. Voice: ElevenLabs "Jessica" with trainer settings

- `ELEVEN_VOICE_ID=cgSgspJ2msm6clMCkdW9` (Jessica — "Playful, Bright, Warm", young female: the excited-girl
  trainer; Sarah `EXAVITQu4vr4xnSDxMaL` is the calmer fallback if Tri prefers). Model `eleven_flash_v2_5`.
- `eleven.py` sends `voice_settings {stability 0.45, similarity_boost 0.8, style 0.35, use_speaker_boost true}`
  (configurable `ELEVEN_STABILITY`, `ELEVEN_STYLE`), so the voice is lively but not shouty.
- New config `ELEVEN_RUNTIME_TTS` (default `0`): when off, `eleven.tts()` returns a cached `/audio/...` if the
  file exists and `None` otherwise (no network). The CLI generators pass `force=True` to bypass the gate.
- `audio_name()` already keys on voice id, so switching voices never reuses Sarah's old files.

### 2. Scripted trainer lines (`cue_library.py`)

New hand-written `SCRIPTED_CUES` (never regenerated by Gemini, like `FIXED_CUES`), each with 1–3 variants:

| id | lines (variant 1) | when |
|---|---|---|
| `raise_hand` | "Raise your hand when you're ready to start!" | `awaiting_gesture` |
| `lets_go` | "Perfect! Let's get started." | `gesture` |
| `count_1` … `count_20` | "One!" … "Twenty!" | good `rep` → index |
| `halfway` | "Halfway there, you're doing great!" | good rep at ⌈target/2⌉ (only if not also last) |
| `last_rep` | "Last one, make it count!" | good rep at target − 1 |
| `session_done` | "That's your whole session. Amazing work today!" | `session_summary` |
| `calling_contact` | "I'm calling your emergency contact now. Stay still, help is on the way." | `alert step=escalated` |
| `contact_on_call` | "Your emergency contact is on the line. I'm staying right here with you." | `alert step=call_ongoing` |
| `call_failed` | "I couldn't reach your contact. If anyone is nearby, please call 911." | `alert step=call_failed` |

Existing ids reused: `countdown_3/2/1`, `set_start`, `set_done`, `pause`, `resume`, `rest`, `check_in`,
`im_ok_thanks`, `greeting_generic`, corrections (`knees_out`, …). `--generate-audio` voices everything that
has no MP3 (counts are one variant each). Total new text ≈ 600 chars; the full library ≈ 2,600 chars.

### 3. Trainer agent (`server/agents/trainer_voice.py`, class `TrainerVoice`)

Subscribes to bridge events like the Coach (`bridge.subscribe_events`) and the hub's agent events for
`alert`/`session_summary`. For each trigger above it picks a variant (`cue_library.pick`) and emits one hub
event:

```json
{"type": "say", "session_id": "...", "t": 1760.1, "id": "count_3", "text": "Three!", "audio_url": "/audio/count_3_1.mp3"}
```

Rules:
- Only `quality == "good"` reps are counted aloud (the "correct rep" placeholder); a `fix_form` rep is left to
  the existing correction `cue`. Count index = the rep's `index` field (the engine's count), capped at 20.
- Never talks over safety: while an incident is open (`fall confirmed`, `cue check_in`, `alert detected` until a
  closing step) the agent emits only the call-flow lines.
- Dedupe: the same `id` is not repeated within 1.5 s; `set_done` is spoken only when `SessionVoice` produced no
  audio for `summary_ready` (i.e. runtime TTS off) — it waits up to 1 s for `summary_ready.audio_url`.
- No AI, no network, pure event → line mapping; fully unit-testable with a fake hub.
- Wiring: constructed in `server/main.py` lifespan next to the Coach; `say` added to
  `DEVICE_EVENT_TYPES` (`server/devices.py`), `CAPTION_SOURCES` (`engine_bridge.py`, so `live.caption` carries
  the spoken text), `server/samples/ws_events_say.json` + `SERVER_EVENTS` in `test_samples.py`, README event
  table.

### 4. LCD kiosk changes (`device/kiosk`)

Pages stay the same; additions only.

- **Audio**: `say` joins `AUDIO_EVENTS`. `AudioPlayer` gets `onSpeaking(bool)` (play/ended/pause/error); `main.js`
  dispatches `{channel: "speaking", msg: {on}}`; reducer stores `speaking`; `view()` exposes `speaking`.
- **Mascot animation**: `#stage[data-speaking="true"] #mira` gets a `talk` keyframe (quick 0.35 s bob + 1.5°
  tilt, layered with the mood animation via a wrapper `.mascot`), the caption bar's voice icon becomes three
  animated bars (`.voice-bars`, CSS only). Gesture screen: Mira waves (`wave` keyframe on `.mascot`,
  rotate ±4° at 1.2 s). Countdown: the number scales in (`pop` on change via a `data-tick` attribute).
  Rep screen: `#rep-now` pops (`pop` 0.3 s) when the count changes (view sets `data-rep` and CSS animates on
  attribute change via a re-triggered class), count sparkles (`.s-count`) twinkle during `cheering`.
- **Gesture copy**: hero "Raise your hand to start", eyebrow "WHENEVER YOU'RE READY", hint "A thumbs up works
  too." Both icons stay.
- **Fall screen call status**: reducer keeps `alertStep` and `alertMessage` from `alert` events (reset on
  `arrived`/close). View adds `callStatus`: `null` before escalation; `{phase: "calling"|"on_call"|"ended"|
  "failed", message}` from steps `escalated`/`call_registered`/`call_retry` → calling, `call_ongoing`/
  `call_update`/`patient_responded` → on_call, `call_ended`/`acknowledged` → ended, `call_not_connected`/
  `call_error`/`call_failed`/`call_watch_timeout` → failed. New `#call-status` line under the gestures
  (textContent of `alert.message`), phone icon pulses while calling; "CALL 911" block stays and is emphasised
  when `show_call_911` is true or phase is failed.
- **Tests** (`node --test`): reducer/view for `say` caption, speaking flag, alert step → callStatus mapping,
  reset on `arrived`, priority unchanged; audio test for `onSpeaking`.
- **README**: event table (+`say`), screens table (call status), voice section.
- `device/lcd-web` (static demo copy): copy the kiosk's `css/kiosk.css`, `index.html` sections and the
  mascot/caption markup changes so the shareable demo page matches; add `say`/call-status demo content to
  `js/demo.js` fixtures.

### 5. Emergency call flow (no new behaviour, narrated)

Eric's fall detector → `fall {stage: confirmed}` → Guardian `cue check_in` (LCD fall screen, "Are you okay?")
→ no gesture in `CHECKIN_TIMEOUT_S` → `alert escalated` → Retell call (or log-only simulator when
`CALLS_DISABLED=1`) → `call_*` steps. The trainer agent voices `calling_contact`, `contact_on_call`,
`call_failed`; the LCD shows each step's message. Demo trigger: `POST /demo/trigger_fall` (needs
`DEMO_TOOLS_ENABLED=1`).

### 6. Deploy

`tools/deploy_vultr.sh LCD-agent` after tests pass (ships committed MP3s; no ElevenLabs key needed on the
box). Shareable link stays `http://45.76.255.253:8000/lcd/<LCD_LINK_KEY>` (key lives only in the box's `.env`).
