# LCD Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mira's LCD speaks every screen in one ElevenLabs trainer voice (counting correct reps aloud, narrating the emergency call), and the mascot animates while she talks.

**Architecture:** A new server agent `TrainerVoice` maps engine/hub events to pre-recorded lines from the cue library and emits `say` events; the kiosk plays them, shows the caption, and drives a `speaking` animation state. ElevenLabs is used only offline (CLI) to voice the library once; MP3s are committed so the Vultr box needs no key.

**Tech Stack:** FastAPI/asyncio server (Python 3.12, pytest), vanilla ES-module kiosk (node --test), ElevenLabs REST (`eleven_flash_v2_5`).

Spec: `docs/superpowers/specs/2026-10-11-lcd-agent-design.md` (read it first).

## Global Constraints

- ElevenLabs free tier: ≈8,000 characters left this month. The running server must **never** call ElevenLabs unless `ELEVEN_RUNTIME_TTS=1` (default `0`). Only the CLI generators synthesize.
- Voice: `ELEVEN_VOICE_ID=cgSgspJ2msm6clMCkdW9` (Jessica), model `eleven_flash_v2_5`, `voice_settings {stability 0.45, similarity_boost 0.8, style 0.35, use_speaker_boost true}`.
- Kiosk: no `innerHTML`, no inline `style=`/`onclick=`/`<script>` (CSP `script-src 'self'; style-src 'self'`), server text via `textContent` only, audio only for same-origin `/audio/*.mp3`. Screens keep their current layout; additions only.
- New WS event type is exactly `say` with payload `{type, session_id, t, id, text, audio_url}`.
- Do **not** run the full test suites between tasks (pytest / `node --test` for the whole directory). Each task writes its unit tests and may run **only its own new test file** once to check it loads; the suites run once at the end.

### Task 2: Server — `TrainerVoice` agent and wiring

**Files:**
- Create: `server/agents/trainer_voice.py`
- Modify: `server/main.py` (construct + subscribe next to the Coach; close on shutdown), `server/devices.py` (`"say"` in `DEVICE_EVENT_TYPES`), `server/engine_bridge.py` (`CAPTION_SOURCES["say"] = "text"`), `server/samples/ws_events_say.json` (new), `server/tests/test_samples.py` (`"say"` in `SERVER_EVENTS`), `README.md` event table (one row for `say`), `server/samples/README.md` if it lists samples.
- Test: `server/tests/test_trainer_voice.py`

**Interfaces consumed:** `cue_library.pick(id)` (Task 1). Study `server/agents/session_coach.py` for the `on_event` + `bridge.subscribe_events` pattern, `server/agents/haptics.py` for the smallest example of an agent that emits on the hub, and how `main.py` wires them (also how hub agent events such as `alert` reach subscribers — `hub.emit` output goes to `engine_bridge.on_agent_event`; the agent must get `alert` and `session_summary` too, so subscribe to whatever stream carries both engine and agent events, or subscribe to both and dedupe by `(type, t)`).

**Interfaces produced:**
- `class TrainerVoice(hub, sessions, *, pick=cue_library.pick, now=time.time)` with `async on_event(ev: dict) -> None`, `async close() -> None`.
- Emits `hub.emit("say", {"session_id", "t", "id", "text", "audio_url"})`.
- Mapping (all via `pick`): `awaiting_gesture→raise_hand`, `gesture→lets_go`, `countdown{n}→countdown_{n}` (3,2,1 only), `rep{quality=="good", index=i}→count_{min(i,20)}` plus `halfway` when `i == ceil(reps_target/2)` and `i < reps_target-1`, `last_rep` when `i == reps_target-1` (reps_target from the event or the last `countdown`/`arrived` for that session; skip both extras when unknown), `paused→pause`, `resumed→resume`, `set_done→set_done` **only if** no `summary_ready` with a non-null `audio_url` arrives for that session within 1.0 s (use an `asyncio` task; cancel it when such a `summary_ready` arrives), `session_summary→session_done`, `alert step escalated|call_registered→calling_contact`, `alert step call_ongoing→contact_on_call`, `alert step call_failed|call_not_connected|call_error→call_failed`.
- Incident hold: `fall{stage: confirmed}`, `cue{id: check_in}`, `alert{step: detected}` set `incident=True` for the session; `alert{step in resolved|closed|resolved_by_therapist}` clears it. While `incident` is true only the three call-flow lines are emitted.
- Dedupe: identical `id` within 1.5 s is dropped. Unknown `pick` result (`None`) → nothing emitted.

- [ ] Write `server/tests/test_trainer_voice.py` first with a fake hub (`emit(type, payload)` appends to a list) and a fake `pick` returning `{"id", "text": id.upper(), "audio_url": f"/audio/{id}_1.mp3"}`; cover: gesture prompt, countdown 3/2/1, good rep 1..3 counts and a `fix_form` rep is silent, halfway/last_rep at target 10 (indices 5 and 9), `set_done` spoken after 1 s when no summary audio (use `now` injection or `asyncio.sleep(1.05)`), `set_done` suppressed when `summary_ready{audio_url:"/audio/x.mp3"}` arrives within 1 s, incident hold (check_in then a good rep → silence; `alert escalated` → `calling_contact`; `alert closed` clears), dedupe within 1.5 s, `say` payload shape.
- [ ] Implement `trainer_voice.py` with a module docstring explaining it is the LCD's trainer voice (no AI, pre-recorded lines only, free-tier budget).
- [ ] Wire it in `main.py`; add `say` to `DEVICE_EVENT_TYPES` and `CAPTION_SOURCES`; add the sample `{"type":"say","session_id":"s_01","t":1760000000.0,"id":"count_3","text":"Three!","audio_url":"/audio/count_3_1.mp3"}`; add `"say"` to `SERVER_EVENTS` in `test_samples.py`; add the README row.
- [ ] Run only `.venv/bin/python -m pytest server/tests/test_trainer_voice.py -q`; commit.
